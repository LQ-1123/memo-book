# 个人 RAG 知识库 — 需求规格

> 状态：已与用户逐轮确认（2026-08-31）
> 下一步：架构设计 → 实施计划

## 1. 项目定位

个人知识库系统：将各类文档、网页、笔记统一入库，通过本地 API 服务提供**检索**与**生成式问答**能力。数据全部存放在本机，模型推理调用国内 API（智谱）。

- 从零开始积累，无大规模存量导入压力
- 单用户个人使用，非多人产品

## 2. 内容与规模

| 维度 | 要求 |
|---|---|
| 文档类型 | Markdown / 纯文本、PDF（论文/书籍/报告）、网页剪藏 / HTML、代码 / 技术文档 |
| 扫描件 | **需要 OCR**：存在图片型 PDF（扫描版书籍/论文），文本层缺失时须 OCR 后入库 |
| 规模 | 上万篇文档、多 GB 原始文件 |
| 存量 | 基本从零开始，靠日常逐步积累 |

## 3. 功能需求

### 3.1 入库（两路）
1. **监听本地文件夹（唯一文件通道）**：所有本地文件——不论大小——统一放入监听目录入库（设想场景如 Obsidian vault、剪藏目录、PDF 书籍），服务自动扫描并增量感知新增/修改/删除。**一期不设 HTTP 上传接口**；若二期前端需要远程上传，届时增加"上传后转存监听目录"的接口即可
2. **URL 抓取**：给定网页地址，自动提取正文入库（配合网页剪藏场景）

通用要求：去重（同内容/同文件变更走更新而非重复入库）、解析失败可追溯、入库状态可查询。

### 3.2 检索
- 混合检索：向量（语义）+ 关键词（BM25），融合排序
- Rerank 重排（效果优先，接受延迟与成本）
- 返回相关片段 + 来源定位（文件名、页码/标题、原文引用），供调用方展示引用
- 支持按文档类型、来源、时间等元数据过滤

### 3.3 问答
- 基于知识库的生成式问答（RAG），回答**必须带引用**
- 支持流式输出（SSE），为未来前端做准备
- 底层检索接口与问答接口并存，Agent/脚本可直接用检索

### 3.4 管理
- 文档列表 / 详情 / 删除 / 重新索引
- 入库任务状态与失败重试

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 部署 | 本机（macOS）运行；**仅局域网暴露**；Docker 可用（用于 Qdrant 等基础设施） |
| 安全 | API Key 认证（每设备/调用方一个 token，支持多 key） |
| 数据边界 | 文档原文、向量、索引全部在本机；仅 embedding / LLM / OCR（如选 API 方案）调用时文本出网 |
| 模型 | 智谱 API（**已有 key**）：embedding-3 + GLM 问答；配置层兼容 OpenAI 接口格式，可随时换厂商 |
| 性能预期 | 万级文档规模下检索秒级响应；入库支持后台批量处理，不阻塞查询 |
| 可维护性 | 单人可运维，配置集中在一份 env/配置文件 |

## 5. 技术选型（已确认）

- **后端**：Python + FastAPI
- **向量库**：Qdrant（Docker），混合检索用其 dense + sparse 向量与融合能力；关键词索引、文档元数据存储方案在架构设计阶段细化
- **OCR**：倾向本地 PaddleOCR（中文效果好、批量免费）；扫描页检测 → OCR 兜底，架构留扩展位
- **MCP 服务**：**二期交付**。一期只做 HTTP API，但接口设计保持 Agent 友好（检索/问答分离、引用结构化）
- **前端**：不在一期范围，接口按前端需要预留（流式输出、CORS）；上传接口二期按需补充

## 6. 范围划分

**一期（本次交付）**
- FastAPI 服务 + API Key 认证（局域网）
- 两路入库：文件夹监听、URL 抓取
- PDF（含 OCR 兜底）/ MD / HTML / 代码 解析入库
- 混合检索 + rerank + 元数据过滤
- RAG 问答（非流式 + SSE 流式），回答带引用
- 文档管理接口（列表/详情/删除/重建索引）
- Docker Compose（Qdrant + 应用）

**二期（规划中）**
- MCP server，接入 ZCode 等 AI 客户端
- Web 前端

## 7. 开放问题（设计阶段决定）

1. 关键词索引实现：Qdrant sparse vector（fastembed BM25）vs SQLite FTS5 并行索引
2. rerank 方案：本地 bge-reranker（CPU 可跑但占资源）vs 国内托管 API（如 SiliconFlow）
3. OCR 方案确认：PaddleOCR 本地 vs GLM-4V 视觉 API（涉及成本与速度权衡）
4. chunk 策略：按文档类型差异化（代码按函数/块、MD 按标题层级、PDF 按页+段落）
5. 文件监听实现：watchdog 轮询 vs 事件驱动（macOS FSEvents 兼容性验证）
